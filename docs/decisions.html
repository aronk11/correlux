ALL 27 DESIGN DECISIONS1. Record architecture decisions2. Go and Bubble Tea v2 for a single static binary3. Applications, not resource types, are the primary navigation model4. The domain layer must not know that a terminal exists5. Remote data carries an explicit lifecycle and a generation counter6. No global cache at startup: load lazily, within the active scope7. Switching context inside Correlux never writes to the kubeconfig8. Production contexts are classified heuristically and guarded by default9. Never encode meaning in colour alone; degrade to ASCII10. The diagnosis engine is deterministic; AI is an optional explanation layer11. Trunk-based development with feature branches and Conventional Commits12. Task instead of Make13. Resources are rendered from the API server's own tables14. Load is tested on a real API server, with pods that never run15. Every commit is signed16. Applications are inferred from the cluster, not declared to Correlux17. The screen reloads on a timer the user turns on, not on watches18. A diagnosis is built from evidence fetched on demand, not from a cache19. A fleet overview across several kubeconfig contexts, read-only20. Every change goes through one gate, and Correlux never edits for you21. Correlux says when it is out of date, and that is the only thing it asks22. A table is ordered on the client, and its columns follow the width23. A detour from an investigation remembers where it was opened from24. Inspect Helm releases through Helm and reconcile Flux through its APIs25. Troubleshooting sessions have explicit identity and bounded lifetimes26. Bounded investigation reports with explicit evidence gaps27. Air-gapped operation is an explicit session policy

Adding one

Copy the structure of an existing record, take the next number, and open it with your pull request. Never edit an accepted ADR to change its decision: write a new one that supersedes it, and mark the old one superseded by ADR N.
