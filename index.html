A FEW GOOD QUESTIONS

Before you ask.

Is this a K9s replacement?+

Correlux is inspired by K9s, with a different starting point: applications and their health. Use it when you want connected evidence and a path from “something is broken” to “I know why.” It is still early software; the roadmap is public.

Does anything run inside my cluster?+

No additional component. Correlux talks to the Kubernetes API from your terminal using your existing credentials and permissions. There is no agent, server or CRD to deploy. Live resource usage optionally uses the metrics API. Troubleshooting Jobs and ephemeral debug containers are created only when you explicitly confirm them.

Is the WHY engine powered by AI?+

No. Twenty-five deterministic rules inspect evidence from your cluster. Findings include the evidence, confidence and what to check next. When the evidence cannot establish a cause, Correlux says so.

Can it change production resources?+

Yes. Scale and edit are available, with explicit confirmation; edits show a diff. Contexts identified as production require their name by default. Interactive shells also require production confirmation. Kubernetes RBAC still controls what you can do. The fleet overview is read-only.

Can I use it without Internet access?+

Yes. Transfer a release archive and run correlux --air-gapped. Automatic and manual update checks are disabled. Configure debug.registryMirror or explicit internal images; use imagePullPolicy: Never for preloaded images. Kubernetes and your authentication helpers still need reachable internal endpoints. See the air-gapped guide.

How mature is Correlux?+

Early and actively evolving. Applications, diagnosis, resource browsing, logs, fleet groups, usage, scale, edit, delete, restart and cordon are implemented. Helm operations, Flux reconciliation, troubleshooting sessions, connected investigations and air-gapped operation are available too. See the release notes for your version and the development roadmap for what comes next.
